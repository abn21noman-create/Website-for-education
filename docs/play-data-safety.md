## Full deletion behavior

The client never receives a Supabase service-role key. It invokes the `delete-account` Edge Function with the signed-in user’s JWT after password reauthentication. The function:

1. accepts only `POST` from allowlisted production, Android app-assets, preview, or local development origins;
2. verifies the bearer token with Supabase Auth;
3. requires a sign-in no more than ten minutes old;
4. ignores browser-supplied user IDs and targets only the verified user;
5. uses the server-only service-role environment credential to hard-delete that Auth user; and
6. relies on the `auth.users` deletion trigger and Auth foreign keys to remove associated rows transactionally.

Deleted live data includes Auth identity/session data, profile, private study and Life Hub records, Cloud Vault, student pulse, leaderboard consent, administrator membership/allowlist entry if relevant, authored community questions/replies, and votes. Threads authored by the user are removed, including replies inside those threads. Vote totals on surviving questions are recomputed.

After a successful response, the initiating client clears that account’s current local `hsc28_*` values, account-space snapshots, guest migration archive pointer, reset metadata, queued writes, and local Supabase session. Other accounts and unrelated guest work in the same browser remain untouched. Exported JSON/Dropbox copies and another offline device cannot be remotely erased and are disclosed separately.

## Separate study-data reset

`hsc28_clear_my_study_data()` is **not** account deletion. It keeps the Auth user, profile identity, and community contributions while resetting private learning records. UI copy must continue to distinguish it from **Delete account and all associated data**.

## Retention statement

Deletion removes data from the live application immediately after the server confirms success. Limited residual copies may remain temporarily in encrypted provider backups or security logs for provider rolling operational retention, abuse investigation, or legal duties. Such copies are not available through the application and expire or are overwritten under provider schedules. Do not promise an exact backup duration unless the active Supabase/Vercel plan and policies have been verified for that release date.
